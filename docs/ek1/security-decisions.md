# Security Decisions

## D-01 Token Gate And Owner-Scoped Store

Решение: все маршруты `/notes` проверяют заголовок `Authorization: Bearer <NOTES_API_TOKEN>`, а операции чтения, изменения и удаления проходят через методы `NotesStore`, которые фильтруют записи по `ownerId`.

Обоснование: для EK1 продукту нужна минимальная, но явная граница доверия. Bearer token проще полноценной учетной системы, но уже позволяет показать обязательную авторизацию и единое место проверки доступа. Фильтрация по `ownerId` сохраняет будущую совместимость с настоящими пользователями.

Связи: `T-01`, `T-02`, `T-03` -> `SR-01`, `SR-02`.

Будущие проверки:

- `D-01-V1`: интеграционный тест подтверждает `401` для `/notes` без токена;
- `D-01-V2`: тест хранилища подтверждает, что заметка другого `ownerId` не возвращается и не раскрывается через `404`;
- `D-01-V3`: при переходе к реальной авторизации заменить статический token на сессию или JWT с проверкой подписи и срока действия.

## D-02 Strict Input Boundary

Решение: JSON-тело читается с лимитом 32 KiB, затем каждое поле заметки валидируется перед сохранением.

Обоснование: заметка является основным пользовательским объектом. Проверка типов, длины и количества тегов защищает минимальную основу от некорректных данных и простого расхода памяти.

Связи: `T-04`, `T-05` -> `SR-03`, `SR-04`.

Будущие проверки:

- `D-02-V1`: тесты на пустой `title`, слишком длинный `content`, некорректный `tags`;
- `D-02-V2`: тест запроса с телом больше 32 KiB;
- `D-02-V3`: при появлении БД добавить ограничения на уровне схемы хранения.

## D-03 Uniform JSON Errors And Minimal Headers

Решение: ошибки API возвращаются единым JSON-форматом без stack trace, а ответы получают `X-Content-Type-Options: nosniff`.

Обоснование: единый формат ошибок упрощает клиентскую обработку и снижает риск случайного раскрытия внутренних деталей. Заголовок `nosniff` задает базовую защиту для JSON API без усложнения архитектуры.

Связи: `T-06`, `T-07` -> `SR-05`, `SR-06`.

Будущие проверки:

- `D-03-V1`: тест подтверждает отсутствие stack trace в ответах на неожиданные ошибки;
- `D-03-V2`: тест подтверждает наличие `X-Content-Type-Options: nosniff`;
- `D-03-V3`: при появлении frontend добавить CORS-политику и CSP для клиентской части.

## Цепочка для защиты

Основная цепочка:

`T-01 Unauthorized Note Access -> SR-01 Authentication Required + SR-02 Note Isolation -> D-01 Token Gate And Owner-Scoped Store -> D-01-V1/D-01-V2`.

Почему решение подходит: оно закрывает наиболее прямой риск сервиса заметок - доступ к личному содержимому без права. Даже в минимальной версии API все операции с заметками проходят через одну проверку bearer token, а доступ к объектам идет через owner-scoped методы хранилища.
