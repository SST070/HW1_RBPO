# Security Requirements

## SR-01 Authentication Required

Все операции с заметками должны выполняться только при наличии корректного bearer token.

Критерии приемки:

- `GET /health` доступен без токена;
- `GET /notes`, `POST /notes`, `GET /notes/:id`, `PATCH /notes/:id`, `DELETE /notes/:id` без корректного токена возвращают `401`;
- сервис не запускается без `NOTES_API_TOKEN`.

Связанные угрозы: `T-01`, `T-02`.

## SR-02 Note Isolation

Пользователь не должен получать доступ к заметкам другого владельца.

Критерии приемки:

- хранилище выбирает заметки только по `ownerId`;
- чтение, обновление и удаление чужой заметки возвращают `404`, а не раскрывают факт существования записи.

Связанные угрозы: `T-01`, `T-03`.

## SR-03 Input Validation

Сервис должен проверять недоверенные поля заметки перед сохранением.

Критерии приемки:

- `title` обязателен и после trim имеет длину 1-120 символов;
- `content` имеет длину не более 10000 символов;
- `tags` является массивом строк, содержит не более 12 тегов, каждый тег имеет длину 1-32 символа;
- некорректные данные возвращают `400`.

Связанные угрозы: `T-04`, `T-05`.

## SR-04 Request Body Limit

Сервис должен ограничивать размер JSON-тела запроса.

Критерии приемки:

- тело запроса больше 32 KiB отклоняется с `400`;
- некорректный JSON отклоняется с `400`.

Связанные угрозы: `T-05`.

## SR-05 Safe Error Responses

Ответы об ошибках не должны раскрывать stack trace, переменные окружения или внутреннее устройство процесса.

Критерии приемки:

- ошибки возвращаются в формате `{ "error": { "code": "...", "message": "..." } }`;
- неожиданные ошибки получают общий код `internal_error`;
- в ответе нет stack trace.

Связанные угрозы: `T-06`.

## SR-06 Minimal Security Headers

JSON-ответы должны снижать риск неверной интерпретации содержимого клиентом.

Критерии приемки:

- каждый ответ сервиса содержит `X-Content-Type-Options: nosniff`;
- JSON-ответы содержат `Content-Type: application/json; charset=utf-8`.

Связанные угрозы: `T-07`.

## SR-07 Version Observability

Оцениваемая версия должна быть зафиксирована в Git и проверяема локально.

Критерии приемки:

- в репозитории есть исходный код запускаемого API;
- в `PROJECT.md` есть команды запуска и проверки;
- есть commit hash или tag `ek1`, который указывает на оцениваемую версию.

Связанные угрозы: `T-08`.
