# Contributions

Файл фиксирует наблюдаемый вклад участников для EK1. Если команда состоит из одного человека, разделы `M1` и `M2` можно объединить при сдаче, но важно сохранить конкретные результаты и быть готовым объяснить их на защите.

## M1: продуктовая граница и техническая основа

Конкретные результаты:

- Сформулировал идею Notes Service, основные пользовательские сценарии и границу доверия в `PROJECT.md`.
- Реализовал минимальный запускаемый HTTP API в `src/http.ts` и `src/main.ts`.
- Реализовал in-memory хранилище заметок и доменную модель в `src/store.ts` и `src/types.ts`.
- Подготовил команды запуска и проверки в `README.md`.
- Проверил, что проект запускается из отдельного репозитория через `pnpm install`, `pnpm test`, `pnpm build`.

Зона понимания для защиты:

- объяснить, какие данные считаются недоверенными;
- показать, где проверяется bearer token;
- показать, как работает CRUD заметок;
- объяснить, почему на EK1 выбран in-memory store.

## M2: безопасность, угрозы и проверки

Конкретные результаты:

- Подготовил требования безопасности `SR-01` - `SR-10` в `docs/ek1/security-requirements.md`.
- Подготовил модель угроз `T-01` - `T-11` и выделил приоритетный набор в `docs/ek1/threat-model.md`.
- Описал проектные решения `D-01` - `D-05` с обоснованием, альтернативами и будущими проверками в `docs/ek1/security-decisions.md`.
- Составил матрицу трассировки `T-* -> SR-* -> D-* -> проверка` в `docs/ek1/traceability.md`.
- Добавил сценарий устной защиты и ответы на адресные вопросы в `DEFENSE_GUIDE.md`.
- Расширил тесты в `test/run-tests.ts` для авторизации, валидации, headers и owner isolation.

Зона понимания для защиты:

- объяснить приоритетную цепочку `T-01 -> SR-01/SR-02 -> D-01`;
- обосновать, почему чужая заметка возвращает `404`;
- объяснить разницу между текущими проверками и будущими проверками;
- показать, какие угрозы остаются вне рамок EK1.

## Общая командная готовность

Перед защитой каждый участник должен уметь:

- локально запустить тесты;
- открыть `PROJECT.md` и объяснить границу доверия;
- открыть `docs/ek1/traceability.md` и пройти одну цепочку полностью;
- показать фрагмент кода, который соответствует выбранному решению;
- назвать ограничения текущей версии без попытки представить ее как production-ready продукт.
